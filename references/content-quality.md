# 内容生产与质检

## 1. 选题颗粒度

不要写大词：

- ❌ 社保知识
- ✅ 被裁以后，先去领哪 3 笔钱

至少回答四个问题：

1. 这条给谁看？
2. 他现在正在做什么决定？
3. 不处理会损失什么？
4. 看完下一步能做什么？

优先结构：

```text
身份人群 × 具体场景 × 金额/后果 × 可执行动作
```

## 2. 标题

### S/A 优先级

- **S**：身份人群 + 领钱/补贴 + 数字 + 钱
- **A**：损失 + 数字/期限 + 行动
- **B**：省钱、少走弯路，弱于 S/A
- **C**：纯名词 + 疑问句，原则上不做

### 硬规则

- 默认不超过 20 字。
- 前 6 个字放身份词、金额词或可检索实名词。
- 一条标题只打一个主要点击理由。
- 不编造百分比。
- 不用“了解、须知、解读、盘点、干货、到底、为什么”作为主要入口。
- 标题承诺的内容必须在前 3 秒或第 2 页兑现。

## 3. 视频

默认短版，45–60 秒，一条只讲一个动作或判断。

结构：

```text
缺口钩子 → 是什么/多少钱 → 怎么做 → 边界 → 立场 → 出处 → 关注理由
```

### 缺口钩子

第一句给代价、动作或数字，但不要把答案全说完。

- ❌ “没休年假可以拿 300% 工资，方法如下。”
- ✅ “签一个字，少拿 5,517 块。”

### 中段

- 6–8 个信息点。
- 按代价或决策顺序排，不按时间流水账。
- 每 6–8 秒一个认知变化。
- 每个点尽量能独立成为一张卡片。

### 立场

一句可以被认同，也可以被反驳的观点，必须写清“谁”和“该怎么做”。

### 转发

明确写“转给正在____的那个人”，不要只写“建议收藏”。

### 制作质量门槛

- 旁白一律用真人或高质量自然 TTS。**禁止系统内置机械合成音进入任何交付物**，包括“临时可看版／预览版／样片／零成本版”——零成本不等于可以降配音标准。
- 配音留台账：来源、音色、风格、段数、各段真实时长、总时长。交付前自检：音轨存在、非静音、听感非机械音。
- 旁白稿避免全角冒号等会引入异常停顿的标点，数字读音逐句检查。
- 指定使用动效模板时，必须走模板真实渲染链；本地静图＋运镜只允许作为结构草稿，不得冒充“按模板做出来”的成片，交付时必须说明是模板渲染还是草稿。
- 分段变速时情绪段保持原速、信息段可适度加速，数字句不加速；不要靠大倍速硬压时长，会毁掉情绪和听感。

## 4. 图文

视觉硬规则见 [`image-visual-rules.md`](image-visual-rules.md)。以下任一情况直接退回重做：

- 270px 宽首图预览看不清“谁 + 什么场景 + 能做什么 + 数字/结果”
- 首图是“大抽象词 + 小字解释”，不能连成一句完整承诺
- 用大面积装饰留白挤压核心信息
- 一张卡同时承担定义、资格、例外、流程或对比中的多个类别
- 关键正文、辅助说明或出处低于可读字号，或对比度不足
- 跨卡标题、正文、页脚和字号层级漂移
- 标题写“2笔/3项/5步”，但没有同等数量的独立兑现单元
- 第 2 页没有先解释首图的数字承诺
- 出处被做成不可读脚注
- 装饰线、高亮块或纹理穿字、断句、压过正文

反例：把同一临时救助制度下的“急难型/支出型”两种情形包装成“2笔救助”，再用巨字和小字拆开首图承诺。此类内容即使政策无误也不得发布。

默认 6–8 张，必要时可到 10 张，但必须有结构。

建议：

1. 封面：人群 + 损失/收益 + 数字
2. 总览：第 2 页兑现标题
3. 条件
4. 步骤 1
5. 步骤 2
6. 例外/风险
7. 立场页
8. 可保存清单 + 出处 + 关注理由

每张卡只承担一个信息点。最后一张要能被截图保存。

## 5. 入口一致性

发布前逐项核对：

- 标题说的是哪件事？
- 封面大字说的是哪件事？
- 视频前 3 句或图文第 2 页是否立即兑现？
- 正文是否给出条件、例外和动作？
- 结尾是否还在讲同一件事？

任何一项不一致，都先改内容，不靠改标题救。

## 6. 反同质化

至少轮换以下维度：

- 封面配色
- 封面版式
- 字体
- 视频视觉形态
- 片尾组合
- 文案结构：清单式 / 问答式 / 自测式 / 对比式
- 同日选题
- 发布分钟
- 系列合集或系列钩子

规则：

- 连续 3 条不重复同一视觉组合。
- 连续 2 条不重复文案结构。
- 同一天视频和图文不讲同一选题。
- 同一内容 7 天内不换形式重发。
- 垂类系列不等于同质化；要用合集和系列钩子把系列关系说清楚。

## 7. 发布前检查

### 文字

- [ ] 一篇只讲一个点
- [ ] 标题和封面同题
- [ ] 第 2 页/前 3 句兑现标题
- [ ] 数字有出处
- [ ] 条件和例外写清
- [ ] 无绝对化承诺
- [ ] 无外链、联系方式、二维码、站外导流
- [ ] 无“欢迎评论、私信我、关注我”式低质 CTA

### 视频

- [ ] 目标时长符合配置
- [ ] 字幕一行一句
- [ ] 数字读音已检查
- [ ] BGM 不压口播
- [ ] 有立场句
- [ ] 有明确转发对象或收藏理由
- [ ] 片尾组合与最近内容不同

### 图文

- [ ] 已先看 270px 宽首图预览，再看整套联系表，最后看原图
- [ ] 首图 3 秒内能读清“谁 + 什么场景 + 能做什么 + 数字/结果”
- [ ] 首图是一句完整承诺，不是“大词 + 小字解释”
- [ ] 每张卡只承担一个主要信息类别
- [ ] 关键正文 ≥38px、辅助说明 ≥30px、出处 ≥26px
- [ ] 普通文本对比度 ≥4.5:1，大字文本对比度 ≥3:1
- [ ] 标题数字有同等数量的独立兑现单元，第 2 页逐项列出
- [ ] 跨卡版式、编号、基线和页脚位置一致
- [ ] 出处可读，装饰没有穿字、断句或压过正文
- [ ] `visual-review.json` 为 `pass`，标题、页数和图片清单与发布包一致
- [ ] 图片数量和比例符合配置
- [ ] 标题与首图同题
- [ ] 最后一张可保存
- [ ] 图片顺序无重复或漏页

## 8. 发布包建议结构

```text
publish/<slug>/
├── title.txt
├── body.txt
├── sources.md
├── visual-review.json # 图文必填；视觉复核记录
├── images/            # 图文
│   ├── 01.png
│   └── 02.png
└── video.mp4          # 视频
```
