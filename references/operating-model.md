# 运营模型与例行任务

> 本文件描述人工或当前任务触发时的执行 SOP。技能默认不自行创建、恢复或改写定时任务；
> 任何自动化都必须先获得用户明确授权。

## 1. 核心闭环

```text
账号数据
  → 14 维诊断
  → 今日修正项
  → 明日选题与发布指令
  → 内容生产与质检
  → 排期发布
  → 首评/回复/双池外联
  → 24h / 72h 复盘
  → 回写配置、选题池和话术库
```

每个动作都要绑定一个算法环节：

- **点击**：标题、封面、前 6 个字
- **停留**：开头、结构、信息密度
- **互动**：立场句；问题只在确有价值时使用。该条主要针对自家内容与回复，外联评论按 `outreach.md` 控制问句比例
- **转发**：明确转发对象、可替用户表达的观点

## 2. 每日执行 SOP

以下时间点为示例默认值，以账号配置 `xiaohongshu-ops.yaml` 为准。

### 当天开始或结束前：数据诊断

必须完成：

1. 读取账号总览、笔记列表、违规状态。
2. 对当天发布的笔记和观看 Top 3 读取详情。
3. 按 14 维分析，但只输出最重要的异常和行动。
4. 产出一份可直接执行的「今日/次日运营指令」。
5. 数据缺失写「未取到」，不估算。

产物建议：

- `data/reports/analysis-YYYY-MM-DD.md`
- `data/reports/metrics-YYYY-MM-DD.json`
- `data/reports/daily-brief-YYYY-MM-DD.md`

### 发布窗口前：发布执行

1. 读取当天 brief、排期锁和内容包。
2. 运行配置、发布包和文案检查。
3. 检查是否已有同题内容、是否超每日上限。
4. 上传、填写、设置封面、设置定时或即时发布。
5. 回读平台状态，不以「点击成功」代替「发布成功」。

发布纪律：

- 每天**最多**发配置的发布位（默认 1 条图文 + 1 条视频）；这是上限不是 KPI，允许少发或 0 条。
- 发布前先校准系统时间，早于窗口也不发；错过窗口则跳过，不挪到凌晨或次日补发。
- 当日已存在计划外内容或发布位已被占用时，对应发布位跳过，不新增「补偿性第三条」。
- 发布后从笔记管理页回读当日真实发布条数，确认没有并行任务重复发布。

### 发布后 0–30 分钟

- 给当次新笔记补最多 1 条具体作者首评；每天首评数不超过当日新笔记数。
- 不批量给历史 0 评论笔记补首评。
- 首评不是「欢迎评论」，而是补充一个容易误判的点或具体变量；问题可选，最多一个。
- 记录评论 ID、时间、回读状态。

### 发布后 0–2 小时

- 优先回复真实提问。
- 回复结构：结论 → 依据 → 视情况最多一个反问；能自然收尾时不问。
- 能收尾的评论用表情或简短回应，不硬聊。
- 同一收尾问句 7 天内不重复，连续两条不套同一种「二选一/扣 1 扣 2」结构。

### 全天：双池外联

按 `references/outreach.md` 执行。默认计划上限：

- 同主题互动 15 条 + 爆款帖互动 15 条，合计 30 条（计划上限，不是必须刷满的配额；允许少做或 0 条）。
- 随机分散，不集中爆发；活跃窗口与高峰段按配置（默认晚间为流量高峰，60% 计划位优先落高峰段，凌晨静默段不操作）。
- 晚间场可跨零点，跨零点留言计入新一天配额，不算补量；错过仍跳过，不向后补量。
- 单次执行最多 2 条；两条至少间隔 10 分钟；任意滚动 60 分钟最多 3 条。
- 问句上限总计 5 条、同主题 3 条、爆款 2 条，连续两条不得都是问句。

### 私信

- 默认只读盘点，不自动回复。
- 用户在当前任务中明确点名会话后才可回复；发送前再次核对账号和会话对象。

### 24 小时

记录：曝光、观看、封面点击率、2 秒/5 秒留存（有则记）、完播率、点赞/评论/收藏/分享、涨粉、主页访客（有则记）、流量来源和观众画像（有则记）。

### 72 小时

只在曝光足够且点击率明显偏低时，考虑改一次封面或标题。不要反复改。

## 3. 每周任务

- 比较视频与图文的观看中位数、封面点击率、涨粉率。
- 找出最强 2 条和最弱 2 条。
- 确认下周只改一个主要变量。
- 检查同质化轮换：视觉、结构、片尾、发布时间。
- 更新选题池、已发去重表、外联风格统计。
- 检查主页承接：简介、置顶、前 6 条内容。

## 4. 每月任务

- 重新确认账号定位、目标人群和内容配比。
- 清理失效策略、失效选择器和过期引用。
- 评估外联的真实收益：评论获赞/回复、主页访客增量、关注增量。
- 若平台规则变化，更新配置 yaml、`references/outreach.md` 和 `references/browser-execution.md`，不要继续使用旧参数。

## 5. 默认产出格式

任何「分析」不能只描述现象。每条结论必须包含：

```text
现状 → 目标 → 差距 → 动作 → 算法环节 → 验收指标
```

任何「日报」至少包含：

1. 今天发生了什么
2. 最重要的 1 个发现
3. 今天必须修的 2 件事
4. 明天发什么
5. 哪些数据未取到

## 6. 人工与自动化的边界

机器适合做：

- 读取和整理数据
- 生成候选选题、标题、封面字和脚本
- 生成排版卡片和视频初稿
- 运行规则检查
- 按授权执行重复操作
- 记录日志和提醒

人必须保留决定权：

- 最终发布与否
- 高风险政策、医疗、法律、金融内容
- 品牌、商业合作和对外承诺
- 涉及账号安全、验证码、申诉、付费的操作
