# 浏览器执行与平台适配

## 0. 执行前硬门

真实发布、评论或私信前，先运行：

```bash
python3 <skill-dir>/scripts/doctor.py --config xiaohongshu-ops.yaml
```

并确认你的浏览器适配器健康（能列出标签页、能快照）。依赖健康时不要重复安装或更新。

任何会改变账号状态的动作前，先回读页面当前登录账号；必须与 `xiaohongshu-ops.yaml` 的账号一致。发现切错号立即停止，不得继续评论、发布或回复。

## 1. 适配器原则

Skill 本身不绑定某一个浏览器工具。执行层应通过一个浏览器适配器完成：

```text
list_tabs()
new_tab(url, label)
select_tab(tab_id)
snapshot(tab_id)
read_text(tab_id)
click(tab_id, selector_or_ref)
type(tab_id, selector_or_ref, text)
upload(tab_id, selector, path)
screenshot(tab_id, path?)
network(tab_id, match?)
eval(tab_id, expression?)      # 仅在平台允许且工具支持时
wait(tab_id, condition)
```

用你环境里的浏览器适配器实现这些原语即可（Playwright MCP、Chrome 扩展 MCP 等）；不要把适配器的实现细节写进内容策略。

### 1.1 标签页生命周期硬门

任务开始前先列出标签页并记录基线。不得把用户已有页面当作本任务的工作页。

每次运行生成唯一标签前缀：

```text
XHS-<task>-<YYYYMMDD-HHMMSS>-<seq>
```

规则：

1. 新建标签必须显式写 `label`，且以本次运行前缀开头。
2. 所有 `snapshot/click/type/upload/navigate` 调用都显式带 `tabId`。
3. 优先复用本任务的一个工作标签；同一网址导航时不要再新建。
4. 外联候选最多同时打开 5 个标签，全部属于本任务。
5. 成功、失败、风控停止、超时和用户中断都必须进入清理阶段。
6. 只关闭 label 与本轮前缀完全匹配的小红书标签；不得关闭未标注页面或其他会话页面。
7. 汇报前再次列标签页，确认本轮前缀残留数为 **0**。
8. 清理失败时报告残留 `tabId + label`，不得声称任务完全结束。

清理方式：用适配器的「列标签页」能力筛出 label 精确匹配本轮前缀、且 URL 属于小红书域名的标签，逐个显式关闭；关闭后再列一次核验残留为 0。不要用通用 `close all`、浏览器快捷键或按域名批量关闭代替任务级回收。

## 2. 所有操作必须可核验

发布成功不能只看“点击了发布”：

1. 页面是否出现成功提示
2. URL 是否进入成功页或笔记管理
3. 后台是否显示已发布/定时
4. 详情页是否能打开
5. 笔记 ID 和发布时间是否回读

评论成功不能只看“点击了发送”：

1. 页面是否出现“评论成功”
2. 评论区是否出现自己的文本
3. 评论 ID 或计数是否变化
4. 网络请求是否为 200（工具支持时）

任何一项不具备，就写“未回读”，不要猜成功。

小红书评论区是虚拟列表时，目标楼层可能始终不渲染。此时以 **评论计数 +1 → 刷新后仍 +1 → 输入框清空** 为主证据，并额外记录 POST 200（工具支持时）；台账备注写明“楼层未可见”，不得伪造“页面可见”。

## 3. 发布状态机

### 图文

```text
打开发布页
→ 确认图文入口
→ 上传图片
→ 回读图片数量
→ 填标题
→ 填正文
→ 回读标题/正文
→ 上传或确认封面
→ 设置定时（如有）
→ 发布
→ 校验成功
→ 笔记管理回读
```

发布硬门：

- 每日发布位按配置上限执行（默认 1 条图文 + 1 条视频），除非用户当天明确改规则。
- 只在配置窗口发布（默认图文早间、视频晚间）；提交前重新读取当前时间。
- 发布位已被占用或错过窗口时跳过，不做补偿性补发。
- 发布后从笔记管理页统计当天真实笔记数，确认没有并行会话造成的重复发布。

### 视频

> **操作细节不在本节，在 `references/publish-runbook.md`**——每步的具体路径、selector、坑清单都在那里。
> 发布前必读 runbook §5 坑清单；遇到新坑当场登记回 runbook。

```text
打开发布页
→ 确认视频入口
→ 上传视频
→ 等待转码/封面控件
→ 上传主封面
→ 上传 PK/备选封面（如有）
→ 填标题
→ 填正文
→ 回读
→ 设置定时（如有）
→ 发布
→ 校验成功
→ 笔记管理回读
```

## 4. 坐标和选择器

- 优先使用可读 selector 或无障碍 ref。
- 页面改版后先重新 snapshot，不复用旧 ref。
- 坐标只作为最后手段。
- 用坐标前立即读取实时位置，不要读完后 sleep 再点。
- 上传文件时显式指定 file input，不要让工具自动猜。
- 页面有浮层遮挡时先判断是布局浮层还是验证码；验证码立即停。
- 评论/私信提交按钮必须在发送前实时读取坐标，禁止复用上一轮或硬编码的 y 坐标。

## 5. 验证码与风控

遇到以下任一情况立即停止：

- 验证码
- 滑块
- 登录墙
- 操作频繁
- 评论限制
- 发布失败连续 2 次
- 账号异常提示

停止时记录：

- 时间
- 操作步骤
- 页面提示
- 是否已经产生外部副作用
- 下一步需要用户做什么

不要绕过、不要换号、不要重试到触发更严重限制。

## 6. 外部互动

外联执行前必须：

1. 核对当前账号，读取当天计划，并运行 `outreach_ledger.py status`。
2. 确认当前时间落在 `active_windows`（`00:00-02:00` 深夜尾峰 / `09:30-24:00` 白天+晚间主高峰）内，且**不在**静默窗口 `02:00-09:30`；晚间 18:00–24:00 与 00:00–02:00 是流量高峰，优先执行。晚间场跨零点不算窗口外补量，深夜尾峰计入新一天配额。同时确认当天成功数、单池上限、滚动 60 分钟 3 条和问句上限未超限。
3. 检查作者 7 天冷却、评论质检和是否已有并行会话动作。
4. 可批量打开 3–5 篇候选用于阅读和停留，但一次只发送一条；单轮最多成功 2 条。
5. 发送后按 `references/outreach.md` §6.1 回读。
6. 写入台账时必须提供 `--round-id`；状态不明时先核验，不重复硬发，核验仍不明则记 `skipped`。

同一账号同一时刻只允许一个写操作执行者。并行会话最容易造成重复回复、重复发布和错误对象评论；遇到另一个任务正在操作时，本任务退出，不抢标签页。

### 自己笔记下回复评论

点“回复”后必须先确认：

- `p.content-input`（或当次平台的等效输入框）存在；
- 输入框所在容器包含目标评论原文或目标用户提示；
- 页面没有跳到笔记顶层评论框。

任一步 `not found`、引用为空或绑定不明，立即停止。不得因为找不到回复框就退化为顶层评论。

### 私信

- 默认只读；只有用户在当前任务中明确指定会话并授权回复时才发送。
- 发送前核对会话昵称与用户点名对象一致。
- 成功判据：右侧消息数量 +1 且输入框清空；坐标发送不可靠时使用编辑器聚焦 + Enter（按当前平台实测方式）。
