# 图文视觉负向规则

## 0. 适用场景

本文件用于所有小红书图文卡片、首图、封面和发布前视觉复核。  
它不是风格建议。下列任一项命中，内容必须退回重做，不得以“有设计感”“留白高级”“字号已经不小”解释通过。

用户对这一类内容的基础要求只有一个：**普通用户在手机信息流里，先能看清、看懂，再谈好不好看。**

## 1. 实战反例：临时救助 2 笔

一篇已发布的救助类图文《遇上急事的家庭，这2笔救助先申请》暴露了以下问题：

- 首图把“救助 2 笔”做成巨大抽象词，把“急事家庭、先申请”拆成较小子字，手机缩略图无法一眼读完整承诺。
- 页面大面积留白挤占正文，标题、解释、结论分散在上中下三块，阅读路径跳跃。
- 多张卡的字号、编号、对齐和正文起点不一致，不像同一套模板。
- 一张卡同时装“分类、资格、例外”，把判断和解释混在一起。
- 依据、出处和页脚被压成难以辨认的小字。
- “2笔救助”语义不准确：实际是同一临时救助制度下的“急难型”和“支出型”两种情形，不是两笔可以分别领取的独立救助款。

本反例的裁决：**图文视觉不合格，即使政策事实和正文结构正确，也不得进入发布环节。**

## 2. 十条负向硬规则

### V01 禁止缩略图不可读

必须先生成 **270px 宽**的手机首图预览，在正常查看距离下 3 秒内读清：

- 谁
- 遇到什么场景
- 能做什么
- 数字或结果是什么

任一要素必须靠猜、眯眼、放大才能看清，判 fail。

### V02 禁止“大抽象词 + 小字解释”

首图必须是一句完整、连续、语义闭环的承诺。  
禁止左侧一个巨大抽象词，右侧或下方再用小字补人群、条件、动作。

反例：
- 大字：`救助 2 笔`
- 小字：`急事家庭 先申请`

合格方向必须能连读成一句，例如：
- `急事家庭先申请临时救助`
- `家里突然撑不住，先去乡镇民政窗口`

### V03 禁止空页式排版

不得用大面积装饰留白换“高级感”。  
核心承诺、关键条件、下一步动作必须占据画面的主要视觉区域。页面缩到 270px 宽后只剩少量字可看，判 fail。

### V04 禁止一张卡混装多个信息类别

一张卡只能承担一个主要判断或一个主要动作。  
以下内容不得同时塞进同一张卡：定义、资格、例外、流程、材料、对比、出处。

一张卡出现两组以上并列判断，先拆卡或删掉次要信息。

### V05 禁止低可读字号和低对比

按 1080×1440 画布执行以下下限：

- 关键正文：不低于 **38px**
- 辅助说明：不低于 **30px**
- 出处/页脚：不低于 **26px**
- 普通文本对比度：不低于 **4.5:1**
- 大字文本对比度：不低于 **3:1**

字号达标但字重过细、颜色过淡、背景花纹干扰，仍然判 fail。

### V06 禁止跨卡版式漂移

同一套图文必须统一：

- 标题基线
- 正文起点
- 页脚位置
- 字号层级
- 编号样式
- 边距和段落间距

不能一张卡编号、一张卡不编号；不能上一页居左、下一页居中且没有结构理由。

### V07 禁止不可兑现的数字承诺

标题中的“2笔、3项、5步”等数量，必须对应可以逐个识别、逐个执行或逐个获得的独立单元。

- 同一个福利项目的两种类型，不能包装成“两笔福利”。
- 同一个动作的两个说法，不能算“两个办法”。
- 标题写几个，第二页就要明确列出几个，不能合并后仍沿用原数字。

“2种情形”和“2笔救助”是不同承诺。必须选能兑现的那个。

### V08 禁止第二页不兑现首图

首图出现“几笔、几项、几种、几步”，第 2 张卡必须在两行内先逐项列出它们是什么，再展开条件。  
不得先讲定义、背景、历史、出处，让用户翻到第 3 张还不知道数字指什么。

### V09 禁止出处成为不可读脚注

出处可以比正文小，但必须能读清完整机构名、文件编号或核验日期。  
不得用超淡颜色、超小字号、贴边或被装饰遮挡的方式“象征性放一下”。

### V10 禁止装饰破坏阅读

网格、纹理、箭头、分割线、高亮块和贴纸不得：

- 穿过文字
- 截断句子
- 抢过正文对比度
- 把关键词切成多个视觉碎片
- 遮住标点或数字

### V11 末页品牌锚点（可选转化位，启用后例行必做）

最后一页（end 卡）是转化页。账号启用品牌锚点时，必须让读者看到号、记住名、有动作指引：

- 固定位置品牌锚点：圆形 logo＋账号名＋「点头像 · 去主页关注」类引导徽章。
- 实现方式自定（卡片生成脚本或设计模板均可），但必须渲染到所有 end 卡；logo 素材缺失时不得忽略警告，修正后重出。
- 关注行与 CTA 必须保留；锚点不得与标题、清单、页脚重叠。
- 启用后每篇图文默认执行；漏加视为 V11 fail，退回重做。未启用时不参与硬门检查。

## 3. 生成阶段工作流

1. 先写一句完整的首图承诺，只有通过 V02 后才拆版式。
2. 为每张卡写一个信息点标签，只允许一个主要类别。
3. 标题含数量时，先列出同等数量的独立单元，再写卡片正文。
4. 生成整套页面，不在未检查缩略图前继续做“精修”。
5. 先生成整套联系表和 **270px 宽首图预览**。
6. 先看缩略图，再看原尺寸图。
7. 按 V01–V10 逐项复核（启用品牌锚点时加查 V11）；任何一项 fail，退回修改而不是降低标准。

## 4. 发布前机器门槛

图文发布包根目录必须包含 `visual-review.json`。  
其格式参考 `assets/templates/visual-review.example.json`。

`check_publish_package.py --kind image` 会硬拦截以下情况：

- 缺少复核文件
- 标题、页数或图片清单与当前发布包不一致
- 未声明看过 270px 首图或整套联系表
- 没有记录首图那句完整、可连读的承诺
- V01–V10 任一未通过（required_checks 可按账号扩展）
- 字号或对比度低于配置下限
- 标题含“2笔/3项/5步”等数量，却没有同等数量的独立兑现单元
- 复核结论不是 `pass`

这个文件只证明“复核流程已执行并有记录”，不能自动替代人的视觉判断。Agent 仍必须真的查看缩略图和联系表；不得仅复制模板、批量打勾后宣称通过。
